# Offline Submission Candidate Gate

**Purpose:** Confirm that local release evidence, sanitized public-export records, PayPal Sandbox acceptance records, and proposed URLs refer to one frozen candidate. This is an internal consistency check, **not proof of external readiness**.

## Prerequisites

1. Full, clean Node 22 `pnpm release:verify` with its `verification.json` and all required command logs. A preflight-only run is insufficient.
2. A matching one-commit sanitized `pnpm public:export` manifest. Never expose the private development repository history.
3. Genuine PayPal Sandbox invoice creation/send, buyer payment, authenticated paid financial GET, and signature-verified webhook. Keep the three sanitized stage `evidence.json` files.
4. A proposed public GitHub repository URL distinct from the private development repository, plus a direct public YouTube video URL.

## Create a private manifest

Save the following example as `.data/submission-candidate.json`, replacing **all placeholders** with real files and URLs:

```json
{
  "schemaVersion": "rightsreceipt-submission-candidate-v1",
  "releaseVerification": ".data/release-candidate/run-REPLACE/verification.json",
  "publicExportManifest": ".data/public-export/run-REPLACE/manifest.json",
  "sandboxEvidence": {
    "create": ".data/paypal-sandbox-acceptance/run-CREATE/evidence.json",
    "paid": ".data/paypal-sandbox-acceptance/run-PAID/evidence.json",
    "webhook": ".data/paypal-sandbox-acceptance/run-WEBHOOK/evidence.json"
  },
  "publicRepositoryUrl": "REPLACE_WITH_PUBLIC_GITHUB_URL",
  "youtubeDemoUrl": "REPLACE_WITH_PUBLIC_YOUTUBE_URL"
}
```

Use the exact paths returned by successful commands. All evidence inputs must be regular files within the ignored `.data` directory. Missing files, symlinks, external paths and oversized evidence fail closed. Never commit this manifest, invoice state, buyer payment link, raw webhook capture or credentials.

## Commands

```bash
pnpm submission:candidate:verify
pnpm submission:candidate:check
```

To specify a different private manifest: `node scripts/submission-candidate-check.mjs --manifest .data/submission-candidate.json`.

The checker performs **no network calls**, payment operations or submissions. It verifies the local HEAD and Git tree against both release and sanitized export evidence, the full pinned Node/pnpm release record, and the internal PayPal Sandbox acceptance reconciliation. It prints only fixed diagnostic codes, not raw evidence, URLs, invoice IDs or private paths.

**Turn 090 judge-report binding:** Saved `report.html` must equal the HTML regenerated by the production renderer from the canonical validated `evidence.json`, byte-for-byte. Appended markup or changed narratives that preserve standard labels fail the release, public-export and submission checks. This remains internal evidence consistency, not independent confirmation of PayPal or Devpost. See [Turn 090](../turns/090-p0-exact-judge-report-integrity.md).

**Turn 088 canonical rehearsal integrity:** The release and final submission gates now reuse the strict `projectJudgeRehearsalReport` validator and require the exact canonical JSON serializer output. A one-step fake scenario, invented table names, altered durable rows, an inconsistent repeat hash or extra unrecognized fields can no longer satisfy the internal evidence gate. Passing remains an offline consistency claim, not independent proof of PayPal or Devpost. See [Turn 088](../turns/088-p0-canonical-judge-release-evidence.md).

**Turn 086 judge-evidence hardening:** The final checker now inspects the actual `judge/run-XXXXXX/` rehearsal directory, rather than accepting any nonempty folder. The only permitted files in the run are `evidence.json` and `report.html`. It requires the three ordered successful journeys and three resets, a clean source revision matching the selected commit, matching Node 22 runtime, correct USD 425.00 quote and verified receipt status, zero external calls and credentials, and a report explicitly labeling PayPal as simulated. Missing, oversized, unexpected or symlinked artifacts block with `release_log_or_judge_evidence_invalid`. The test suite includes 12 standalone Node 22 regression cases. This is evidence consistency, not proof of external payment or a completed submission.

**Turn 085 release-evidence hardening:** The final submission checker also reuses the public-export verifier to inspect the actual release command sequence, original stdout/stderr log files and their SHA-256 hashes, committed lockfile identity, timestamps and presence of the judge rehearsal evidence directory. Missing, tampered or incomplete release artifacts add `release_log_or_judge_evidence_invalid` to the blocker list. Having a plausible `verification.json` by itself is insufficient. This check remains an offline integrity test, not independent proof of a real Sandbox payment or external submission.

The possible results are `blocked`, with actionable blocker codes, or `local_records_consistent_external_checks_required`. Even in the latter case, `readyForSubmission` remains `false`. The exit code 0 indicates that local consistency checks passed, **not** that Devpost submission is approved.

## Independent final checks

Before submission, verify separately that the sanitized GitHub repository is anonymously accessible, the public YouTube video is viewable, under three minutes and demonstrates the functioning product, the actual PayPal Sandbox payment and verified webhook occurred in the intended app, and the Devpost entry contains accurate metadata and was submitted before the official deadline.

Use `docs/submission/DEVPOST_DRAFT.md` and `docs/submission/VIDEO_STORYBOARD.md` as drafts until the release has been verified. A matching local JSON package cannot independently prove its own external origin.
