## Defect reproduced in source

The existing `scripts/sandbox-webhook-capture.test.mjs` calls `writeFileSync` in its invoice-state setup and tampered-binding regression, but its `node:fs` import omitted `writeFileSync`. An execution of the official collector test suite would therefore throw a `ReferenceError` at runtime before several essential webhook tests could pass.

**Fix:** Import `writeFileSync` from `node:fs`. No production collector behavior was changed by this fix.

## Added end-to-end local regression

Created `scripts/sandbox-webhook-collector-preflight.test.mjs` and included it in both `paypal:verify` and `sandbox:acceptance:webhook:preflight:verify`.

Unlike earlier standalone local test servers, this regression starts **the actual `startSandboxWebhookCapture` HTTP implementation**. It tests:

1. A live collector's `HEAD` readiness route and same-app callback registration with injected, synthetic OAuth and inventory responses.
2. A changed registered callback failing before any invoice operation.
3. A stopped collector being rejected before OAuth, even though its private route file remains on disk.
4. A `HEAD` readiness check not creating a payment record or consuming the one-shot slot.
5. A synthetic, explicitly unverified `INVOICING.INVOICE.PAID` webhook being captured **after** `HEAD` and binding to an exact synthetic invoice; after capture the collector is terminal and cannot be reused in preflight.

The event in test case 5 is intentionally generated by the test and never claims a genuine PayPal signature.
