# RightsReceipt Synthetic Extraction Dataset v1

**Owner:** Turn 015
**Status:** Generated and committed with reproducible manifest
**Contract:** `rights-extraction-v1`
**Source/license:** Project-authored templates, no scraped third-party corpus, no real buyer data, no paid/external model inference. SPDX `MIT` under the repository license.

## Contents and purpose

These are **synthetic gold annotations**, not learned model predictions, calibrated confidence, or human-verified licensing advice. They prepare the deterministic parser, local model, and safety evaluation in Turns 016 through 020. Every accepted record includes original request text, SHA-256 input identity, all twelve ordered rights fields, resolution states, supported normalized values or explicit abstention, and exact UTF-16 evidence spans.

| Partition | Examples | Template families | Intended use |
| --- | ---: | ---: | --- |
| Training | 960 | 8 | Learn model parameters |
| Validation | 240 | 2 | Select algorithms and thresholds |
| Held-out test | 240 | 2 | Final once-only independent evaluation |
| Unsafe-input quarantine | 24 | separate | Test input rejection, not model training |

The 1,440 accepted examples cover ten categories: complete supported, omission, contradiction, unsupported use, ambiguous language, negation, inert prompt injection, Unicode, numeric boundaries, and mixed paid-social/print channels. Each partition contains every category.

The **17,280 gold field labels** comprise 13,824 resolved, 3,024 unresolved, 144 contradictory, and 288 unsupported. This is still class-imbalanced, so future results must report per-field and per-state accuracy, precision/recall, abstention, and error types rather than only aggregate accuracy.

## Reproducibility

Node.js 22 is sufficient. No network, credentials, GitHub Actions or paid inference service is required.

```bash
node scripts/generate-synthetic.mjs --verify
node --test scripts/generate-synthetic.test.mjs
node scripts/generate-synthetic.mjs --check
```

The root scripts are `pnpm dataset:verify` and `pnpm dataset:generate` when pnpm becomes available. `--verify` regenerates in memory and compares the committed manifest byte-for-byte; `--check` additionally compares all four JSONL datasets without modifying files; `--generate` rewrites all outputs.

The manifest at `data/synthetic/v1/manifest.json` records SHA-256 of the generator source, a fixed per-scenario pseudorandom seed specification, canonical label vocabulary, category/state counts, family allocation, and per-file SHA-256, byte length and row count.

All four data files are checked into Git and regenerated byte-for-byte by the source. The generator is dependency-free Node JavaScript; future Python training can read its JSONL outputs without changing format.

## Record contract

One JSONL record has `dataVersion`, `taskContractVersion`, `exampleId`, `scenarioGroupId`, `templateFamily`, `split`, `category`, `variant`, `intakeEligible`, `inputText`, `inputSha256`, and exactly twelve `fieldLabels`.

Each gold label uses the seven Turn 014 proposal field keys: `fieldName`, `resolutionState`, `normalizedValue`, `evidenceSpans`, `reasonCode`, `reasonNote`, and `confidenceBasisPoints`. Synthetic gold confidence is always null. A resolved label has a supported normalized value and at least one verbatim evidence span; a missing label remains `unresolved/not_stated` with no evidence, and contradictory/unsupported values remain null with evidence and explanation.

Offsets are half-open **JavaScript UTF-16** indices into the original buyer input, not UTF-8 byte indices or offsets into normalized text. Emoji examples explicitly test this distinction. A matching excerpt is provenance, not proof that the phrase semantically entails the annotation.

## Split integrity

Twelve request-frame template families are allocated by whole family: eight training, two validation, two held-out test. Scenario-group IDs, template families, and normalized-text SHA-256 identities are pairwise disjoint between splits. Six baseline/injection pairs per family share a scenario-group ID, stay inside one split, and preserve all licensing gold labels when an untrusted payment/approval instruction is appended.

**Important limitation:** Different families still reuse licensing vocabulary and some clause constructions. This is not proof of semantic independence or generalization to real creator requests. Do not tune on the held-out test data. If data changes, create a new version with new manifest hashes and explicitly record the differences.

The 24 quarantined strings contain script tags, event attributes, dangerous URL schemes and template syntax that the Turn 010 intake must reject. They are excluded from training and test scoring. Inert plain-text prompt injections remain in the learning/evaluation partitions only as buyer text, never as executable instructions or permissions.

## Known limitations and handoff

The corpus uses authored templates and programmatic annotations. No human inter-annotator agreement study exists. It contains no real buyer data and cannot establish deployed precision, legal fitness, identity, ownership, or actual licensing behavior.

Turn 016 owns deterministic extraction baseline tests, Turn 017 owns actual training and artifact export, Turn 018 owns calibration and held-out evaluation, Turn 019 owns persisted versioned source evidence, and Turn 020 owns adversarial behavior. Do not claim an accuracy score, price-setting authority, creator consent, PayPal payment, or effective permission from these data.
